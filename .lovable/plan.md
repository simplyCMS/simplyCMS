# Налаштування Git sync для перенесеного репозиторію

## Огляд

Проєкт був перенесений в іншу GitHub-організацію. Потрібно налаштувати двосторонню синхронізацію коду між Lovable та цим перенесеним репозиторієм.

## Кроки

1. **Перевірити поточний стан Git sync**
   - Відкрити Lovable editor → меню Plus (+) → GitHub.
   - Переконатися, чи підключений зараз якийсь репозиторій.

2. **Відключити старе підключення (якщо є)**
   - У налаштуваннях Git sync відв’язати поточний репозиторій/організацію.

3. **Авторизувати Lovable GitHub App у новій організації**
   - Під час підключення Git sync вибрати нову організацію та надати Lovable доступ до неї.

4. **Підключити перенесений репозиторій**
   - У списку репозиторіїв нової організації знайти та вибрати потрібний репозиторій.

5. **Перевірити двосторонню синхронізацію**
   - Зробити тестову зміну в Lovable і переконатися, що вона з’явилася в GitHub.
   - Зробити тестовий push у GitHub і переконатися, що зміни підтягнулися в Lovable.

6. **(Опціонально) Підключити GitHub API connector**
   - Якщо в майбутньому потрібно з додатку працювати з issues/PRs через GitHub API, підключити GitHub API connector.

## Важливі обмеження

- Lovable підтримує тільки один підключений GitHub акаунт/організацію одночасно.
- Git sync — це не API-коннектор, а вбудована інтеграція в редакторі Lovable.
- Після підключення зміни синхронізуються автоматично в обидві сторони без ручного pull/push.
