# Редизайн за референсом

$ARGUMENTS

Виконай скіл **`redesign-from-reference`**
(`.agents/skills/redesign-from-reference/SKILL.md`) — він джерело правди
методології; ця команда лише двомовний вхід до нього.

**Прочитай скіл повністю ПЕРЕД першою дією** і йди його фазами 0-6 по порядку
(фаза 6 «Шліфування» — опційна, за рішенням користувача). Аргумент вище —
вхідні дані користувача (зазвичай URL і побажання щодо глибини). Якщо URL не
передано — **ЗУПИНИСЬ** і попроси: «Дай URL референс-сайту».

🔴 Фазу 0 (кларіфай + правові межі) не пропускай навіть тоді, коли з аргументу
все «і так зрозуміло»: без узгодженої глибини й межі «що НЕ переносимо» решта
роботи переробляється.

🔴 Другий обовʼязковий чекпойнт — діалог у фазі 1 (крок 1.2): показуєш таблицю
«знайшов ↔ unresolved» від `discover.mjs` і чекаєш відповіді. Продовжувати з
непорожнім `unresolved` без рішення користувача заборонено.

🔴 Третій — фаза 5: пара «референс ↔ наш стенд» тим самим `inspect.mjs` на
КОЖЕН підтверджений тип (наш бік — у `_ours/<pageType>/`), кожна розбіжність
із класом (токен-фіксабельна / дані / структурна-за-дизайном), підсумкова
таблиця показується користувачу. Здати роботу, перевіривши лише `home`,
не можна — виняток тільки для типу, свідомо пропущеного на фазі 1.2.
