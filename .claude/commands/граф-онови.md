# Оновити graphify-граф (код + доки)

Post-commit хук оновлює у графі лише **код** (AST, без LLM). **Документацію**
(семантику `docs/` — architecture, superpowers/specs, superpowers/plans, tasks —
та `.github/instructions/`) хук пропускає — ця команда до-оновлює весь граф, включно з доками.

## Кроки

1. Перевір тулзу: `graphify --version` (якщо немає — `uv tool install "graphifyy[mcp,sql]"`).
   Оновлення тулзи — `graphify-update` (пакет + скіл під нашу `.agents`-конвенцію).
1b. **Якщо з часу попереднього оновлення були rename/видалення файлів** — спершу
   `graphify update . --force` (AST, ~1 хв). Без `--force` граф не прибирає зниклі
   вузли й віддає «привидів»: шлях, якого вже немає. Перевірка:
   `.agents/skills/codebase-research/scripts/orient <перейменований символ>` має сказати,
   що в коді його немає.
2. **Спершу спитай себе, чи потрібен LLM-прохід узагалі.** Свіжість коду й
   path-qualified IDs дає безкоштовний AST (`graphify update . --force`); LLM потрібен
   лише для семантики доків і назв спільнот. 🔴 `--backend claude-cli` **без явної
   моделі бере Opus** і на ~240 чанках з'їдає денний ліміт підписки (спалено 2026-07-29
   у metahub — той самий ліміт спільний з цією підпискою). Якщо семантика справді
   потрібна — дешева модель або зовсім повз Claude:
   ```bash
   GRAPHIFY_CLAUDE_CLI_MODEL=haiku graphify extract . --backend claude-cli
   # або: OLLAMA_BASE_URL=https://ollama.com/v1 OLLAMA_API_KEY=<key> \
   #      OLLAMA_MODEL=gpt-oss:120b-cloud graphify extract . --backend ollama --max-concurrency 2
   ```
   Кеш у `graphify-out/cache/` робить повторні прогони інкрементальними — переекстрактуються
   лише змінені файли.
3. Якщо граф суттєво змінився — перегенеруй звіт і назви спільнот:
   ```bash
   graphify cluster-only . --backend claude-cli --no-viz
   ```
4. Якщо потрібен оновлений візуальний `graph.html` — додай той самий `cluster-only` БЕЗ `--no-viz`
   (важко для великого графа), або легкий `graphify tree --label simplyCMS`.
5. Доповіли користувачу: nodes/edges/communities, з якого коміту граф
   (`graphify-out/GRAPH_REPORT.md` → рядок `Built from commit:`), і динаміку INFERRED-звʼязків.

## Ізоляція від інших репо

Весь стан graphify — **per-repo**: `graphify-out/`, `.graphifyignore`,
`.git/hooks/post-commit`, а `graphify-out/.graphify_root` вказує на `.` (корінь
цього репо). Глобального конфіга немає — інші репо (metahub тощо) свій граф не
бачать і не чіпають.

**Єдиний спільний ресурс — лог ребілду.** Хук за замовчуванням пише його в
`~/.cache/graphify-rebuild.log` — цей файл спільний для **всіх** репо на машині.
У цьому репо лог перенаправлено правкою одного рядка (змінна `_GRAPHIFY_LOG`) у
**обох** хуках — `post-commit` і `post-checkout` — на фактичне значення:

```
_GRAPHIFY_LOG="${HOME}/.cache/graphify/simplyCMS-rebuild.log"
```

🔴 Чекліст після будь-якої переустановки хука:
- [ ] `graphify hook install` **перезаписує** обидва хуки і **скидає** цю правку.
- [ ] Після кожного `hook install` — повторити заміну в обох файлах:
      `sed -i 's|_GRAPHIFY_LOG="${HOME}/.cache/graphify-rebuild.log"|_GRAPHIFY_LOG="${HOME}/.cache/graphify/simplyCMS-rebuild.log"|' .git/hooks/post-commit .git/hooks/post-checkout`
- [ ] Перевірити: `grep -c simplyCMS-rebuild.log .git/hooks/post-commit .git/hooks/post-checkout` → по `1`.
- [ ] `graphify hook install` також створює `.gitattributes` із merge-драйвером для
      `graphify-out/graph.json`. Тека gitignored, тож правило мертве — файл видаляємо.

> `graphify-out/` gitignored — не комітити; росте снапшотами по датах (у metahub —
> 727 MB за ~1.5 місяця), тож старі теки-дати варто періодично чистити. Вартість
> через `claude-cli` — $0 (підписка).
