# ADR-0063: Мерж у `main` робить архітектор; реліз — лише за словом власника

Status: accepted 2026-11-21
Decided by: owner
Supersedes: ADR-0047
Spec: `AGENTS.md` § «Дисципліна git»

## Context
ADR-0047 давав мерж у `main` лише власнику, бо мерж запускає публікацію на npmjs. Але воркфлоу публікації
публікує лише версії, яких ще немає в реєстрі: після мержу PR #68 без бампу версії `pnpm publish -r` вивів
«There are no new packages that should be published». Отже, публікацію запускає бамп версії (`pnpm release`), а не
будь-який мерж.

## Decision
1. Мерж у `main` робить архітектор (сесія з роллю архітектора) через `pr-gate land` після приймання: зелений CI і
   рев'ю лінзою, якої не мав виконавець.
2. Реліз — рішення власника: PR із бампом версії (`pnpm release`) архітектор зливає лише за його словом.
3. Агенти комітять у гілках issues і пушать лише через `pr-gate open --draft`; ніколи force, ніколи `main`.
4. Коміти й PR підписані лише іменем власника, без трейлерів агентів; перевірка після кожного агента, що комітить:
   `git log --format=%B <база>..HEAD | grep -ciE "co-authored|generated with"` дає `0`.

## Why
- Власник 2026-11-21: «я не буду мерджить. це якраз твоя одна із основних робіт, як архітектора - мерджить,
  слідкувати за виконанням, контролювати процес».
- Публікація прив'язана до нової версії: `.github/workflows/publish-packages.yml` (`pnpm publish -r` пропускає вже
  опубліковані версії).

## Rejected
- Мерж лише власником (ADR-0047): власник відмовився 2026-11-21.
- Мерж будь-яким агентом: виконавець не приймає власну роботу; приймання — роль архітектора.

## Consequences
- Виконавці й субагенти не мержать; мержить лише сесія архітектора, і лише через `pr-gate land`.
- PR із бампом версії без слова власника не зливається, навіть коли CI зелений.
