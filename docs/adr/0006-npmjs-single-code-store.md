# ADR-0006: Один склад коду — npmjs; CLI — обгортка над pnpm; маркетплейс — індекс

Status: accepted 2026-07-30
Decided by: owner
Spec: `docs/superpowers/specs/2026-07-30-platform-architecture-design.md` §3, §4.1

## Context
Платформа поставляє ядро, плагіни й теми як пакети.
Потрібно було вирішити, де лежить код і чим є CLI та маркетплейс.
Окремий реєстр коду чи окремий склад для маркетплейсу дали б другий канал оновлень.
Спека фіксує розкладку «що де лежить» як рішення D8.

## Decision
Код ядра, плагінів і тем живе лише на npmjs.
CLI `simplycms` — інструмент поверх pnpm (`add`, `update`, `db:diff`, `doctor`), а не окремий реєстр.
Маркетплейс — індекс-вітрина з метаданими, що вказує на пакети npm; коду він не зберігає.
`@simplycms/plugin-sdk` — звичайний npm-пакет з типами й хелперами.
Платформа живе в одному монорепо.

## Why
- D8: «Склад коду — один: npmjs. CLI — інструмент поверх pnpm, маркетплейс — індекс-вітрина, SDK — бібліотека» (`docs/superpowers/specs/2026-07-30-platform-architecture-design.md` § «2. Зафіксовані рішення власника»).
- Ролі: npmjs — склад; CLI — те, чого pnpm не вміє (конфіг, міграції, типи, сумісність) (`docs/superpowers/specs/2026-07-30-platform-architecture-design.md` § «3. Топологія платформи»).
- Маркетплейс «Коду НЕ зберігає — вказує на npmjs-пакети» (`docs/superpowers/specs/2026-07-30-platform-architecture-design.md` § «3. Топологія платформи»).
- Один монорепо; subtree-дзеркало ядра виведено з експлуатації (`docs/superpowers/specs/2026-07-30-platform-architecture-design.md` § «4.1. Репозиторії, організація, неймінг (доповнення 2026-07-31»).

## Rejected
- Окремий core-репозиторій із git-subtree-синхронізацією — існував лише тому, що репозиторій-застосунок був шаблоном магазину; у цільовій моделі магазини не форкають наш репо (`docs/superpowers/specs/2026-07-30-platform-architecture-design.md` § «4.1. Репозиторії, організація, неймінг (доповнення 2026-07-31»).
- Окремий реєстр для CLI — у джерелі лише заперечено («НЕ окремий реєстр»), причину не записано.

## Consequences
Оновлення ядра в магазині — звичайний `pnpm update` плюс кроки CLI.
Маркетплейс не може хостити код розширень.
Платні пакети — окреме рішення (ADR-0016), воно не змінює цей склад для ядра.
Не можна додавати другий канал доставки коду.
