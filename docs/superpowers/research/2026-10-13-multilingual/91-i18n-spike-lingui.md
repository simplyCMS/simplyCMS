# Спайк B — Lingui 6.12.0 (звіт)

Гілка `spike/i18n-lingui` (коміт `0b9adf4a`, база `b9dead52`), worktree `.claude/worktrees/spike-lingui`. Не мержиться.
Стенд: `pnpm build` (Vite 8.3.2) → `server.mjs`, демо-БД з мовами uk+en, активна тема `solarstore` (з пакета).

## Вердикт

**Lingui технічно ПРОХОДИТЬ усі тверді вимоги (1, 2, 4, граф, розмір), але НЕ проходить критерій «прибирає більше коду, ніж додає»**
і дає мінус на типізації. Для нашого режиму (явні ключі, жодних макросів) Lingui — це лише рантайм-інтерполятор + компілятор `.po`
→ JS; усе, що нам реально потрібно (лінива частина на мову, fallback теми, типи ключів, три рівні), все одно пишемо самі.
Рекомендація: **не переходити**, якщо тільки власник не хоче ICU-множини/`.po`-інструментарій для перекладачів як самоціль.
Множину при цьому дешевше дописати в `lookup.ts` власним `Intl.PluralRules` (узгоджується зі спайком A).

## SSR і гідрація (Playwright на збірці, маркер ідентичності вузлів)

`/en/<товар>`, `/<товар>`, `/en`, `/en/catalog`: `<html lang>` правильний; SSR-вузли ті самі (маркер); сирих ключів 0;
`document.title` = SSR `<title>`; `console.error/warning` і `pageerror` = 0; клієнтський перехід `/en`→`/en/catalog` дає `Catalog — SolarStore`.
Каталог `base` вантажиться динамічним `import()` (окремий чанк на мову) без прогріву до `hydrateRoot` — як і сьогодні.
Англійський товар у демо-БД довелося дозасівати (`catalog_product_texts`, `url_paths`, `languages`) — це стенд, не Lingui.

## Множина

ICU у `msgstr` (`.po` формат Lingui 6 за замовчуванням, а не gettext `msgstr[0..3]`):
`uk` 1→«1 товар», 2→«2 товари», 5→«5 товарів», 21→«21 товар», 22→few, 25→many, 1,5→«1,5 товару»; `en` 1→«1 item», 2→«2 items».
Рантайм викликає `Intl.PluralRules` (скомпільований каталог тримає лише правила, таблиць мов нема). Перевірено і через живий сервер (`5 товарів`/`5 items`).

## Vite 8 і плагіни (запитання 1–2)

- `@lingui/vite-plugin@6.12.0` має `peer vite ^6.3 || ^7 || ^8`; зібрав за Vite 8.3.2 / rolldown без помилок, `.po` імпортувався напряму й давав ті самі чанки. `pnpm dev` НЕ перевіряв.
- Макро-плагін не потрібен: явні id через `i18n._('key')`; `@lingui/babel-plugin-lingui-macro`, `@babel/core`, `@rolldown/plugin-babel` не ставив (див. тертя). Нативний `macroTransform` теж не вмикав.
- Плагін для нас до того ж марний: він компілює лише `.po`, що лежать у `catalogs` конфігу МАГАЗИНУ; `.po` теми/плагіна з `node_modules` не підхопить без переліку пакетів у конфігу (порушення вимоги 4). Фінальний стан гілки — без плагіна, лише `lingui compile` у збірці пакета.

## Тертя

1. **Типізація ключів відсутня** за явних id — потрібен власний генератор union (теми, ядра; плюс `MessageKey` ядра все ще виводиться з TS-каталогів).
2. **Втрачається сенс Lingui**: `extract`/`obsolete`/макро працюють від тексту в коді; з явними ключами `.po` — рукописне джерело правди (конвертер `to-po.mts` — разова міграція).
3. Скомпільований каталог — масиви `["Привіт ",["name"]]`, не рядки: довелося послабити `validateThemeModule` і тип `ThemeMessages` (`Messages` замість `Record<string,string>`); невідомий рантайм-формат для авторів тем/плагінів (сирий `.ts` каталог тепер непридатний — `{name}` без компіляції не інтерполюється, у проді — `Uncompiled message detected!`).
4. `missing`-колбек обов'язковий, інакше шум у логах проду.
5. Сигнатура `createTranslator(catalogs, locale)` змінилась (потрібна локаль для множини): падають лише тестові виклики `typecheck` (translator.test, test-harness/i18n.tsx, e2e support) — 6 місць.
6. Установка Babel-пір'їв (`@babel/core` 8 + `@rolldown/plugin-babel`) розщепила `@lingui/core` на ДВІ копії в pnpm-сторі (різні peer-ключі) — прибрано відмовою від Babel.
7. `admin` частина лишилась необробленою (рядки без компіляції): її теж треба переносити в `.po`.
8. Не перевірено: vitest-пакети, `pnpm dev`, адмінка, плагіни (`usePluginT` лишився на старому `lookupMessage`), `i18n-coverage`/парність-сканери.
