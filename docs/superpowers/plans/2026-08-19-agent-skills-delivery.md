> Середовище: потрібна МЕРЕЖА (проба skills.sh, gh) і права на створення
> репо в org `simplyCMS` (`gh repo create`); Docker/БД НЕ потрібні.
> 🔴 Паралельна задача в іншій сесії розширює МЕХАНІЗМ скіла (скрипти
> `.agents/skills/…/scripts/`) — ця задача скриптів НЕ ЧІПАЄ (лише
> доставку), щоб мерж обох гілок не конфліктував.
>
> 🔴 Після КОЖНОЇ фази репо зелене: `format:check → lint → build →
> typecheck → test`; фінальна фаза — повний ланцюг + `pnpm pilot:pack`
> (Gate CLI міняється).

## Зафіксовані рішення (Р1–Р7)

- **Р1. Стандарт — skills.sh (`npx skills add simplyCMS/agent-skills`)**,
  якщо Фаза 0 не знайде блокера (тоді СТОП і рішення власника). TanStack
  Intent — свідомо ні в цій задачі (канал для скілів усередині
  npm-залежностей; окремий git-репо в нього не вписується).
- **Р2. Джерело правди — монорепо** (`.agents/skills/redesign-from-reference/`);
  дистриб-репо `simplyCMS/agent-skills` — снапшот-дзеркало, наповнюється
  скриптом `scripts/sync-agent-skills.mjs` (модель `template:sync`);
  публікація снапшота — явна дія, не CI-автоматика.
- **Р3. Копія скіла з шаблону скаффолдера знімається** (рекомендація
  задачі; Фаза 0 може задокументувати відхилення) — онбординг веде на
  `npx skills add`. Усі асерти старої моделі (Gate CLI, parity, SYNCED_DIRS)
  оновлюються ЧЕСНО, не видаляються мовчки.
- **Р4. Локальна робоча копія дзеркала в монорепо** — тека
  `agent-skills-repo/` (gitignored) АБО тимчасова тека: вирішує виконавець
  на Фазі 0 за конвенціями skills.sh; головне — parity-тест порівнює вміст,
  який поїде в дистриб-репо, з джерелом правди БЕЗ мережі (фікстурно).
- **Р5. doctor** — нова перевірка «скіл присутній» рівня warn (модель
  наявних мʼяких перевірок), без мережі й без порівняння версій.
- **Р6. README дистриб-репо** — двомовний мінімум (укр основна, короткий
  англ вступ), MIT, інструкція установки/оновлення, посилання на гайд
  монорепо.
- **Р7. Жодних змін у** `scripts/pilot-pack/seed-*`, `supabase/`,
  скриптах самого скіла, темах, view-ах.
