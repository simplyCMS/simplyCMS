## Напрям

### 🎯 SimplyCMS на Simetra (затверджено власником 2026-11-24)

Адмінку SimplyCMS будуємо на платформі [Simetra](https://github.com/VSydorenko/Simetra):
об'єкти магазину (каталог, ціни, доставка, знижки, замовлення) описуються
метаданими Simetra, а схему БД, права, команди, синхронізацію клієнта й
стандартні екрани виводить Simetra. Вітрина й теми лишаються кодом SimplyCMS
зверху. Простір для цього дає те, що магазинів і баз ще немає: SimplyCMS
переробляється під Simetra без поступок сумісності, схема описується з
наявних SQL-міграцій, прийняття старої бази не потрібне.

Хвилю мультимовності даних і повну адмінку цього репо заморожено (мітка
[`frozen`](https://github.com/simplyCMS/simplyCMS/issues?q=label%3Afrozen),
#221, #87): мультимовність даних стає механізмом ядра Simetra — віха
[М5c «Мультимовні дані»](https://github.com/VSydorenko/Simetra/milestone/10),
спека [Simetra#410](https://github.com/VSydorenko/Simetra/issues/410). Канон
мультимовності й дослідження 2026-10-13 цього репо лягли в її основу.

Етапи переходу прив'язані до віх Simetra (стан віх — у GitHub Simetra):

| Етап | Що переходить на Simetra | Віха Simetra |
| --- | --- | --- |
| довідники | розділи, властивості, опції, типи цін, статуси замовлень, доставка, знижки, категорії покупців, банери, мови; товар з модифікаціями, фото | М5 «Повні екрани довідника», М5c «Мультимовні дані» |
| замовлення й облік | замовлення — документ із проведенням; залишки й ціни — регістри | М6 «Документ із проведенням» |
| плагіни й поставка | плагіни — модулі Simetra з власними об'єктами й слотами; магазин — збірка з пакета `simplycms`, плагінів і теми | М7 «Конфігуратор і перша нова сутність» |
| вітрина | читання каталогу вітриною через серверний API Simetra | потребує прогалин Simetra нижче, віху не визначено |

Рішення напряму:

- **Хмара** — окрема база на магазин; кілька магазинів незв'язаних власників
  в одній базі неприпустимі. Основна мова даних — одна на базу, задається при
  створенні магазину й не змінюється.
- **Checkout** без реєстрації: за email платформа створює справжній обліковий
  запис; вхід через Google та інших провайдерів — опційна альтернатива, список
  провайдерів — налаштування платформи.
- **Розширення** — стандартний шлях — плагіни-модулі: власні об'єкти, слоти,
  сторінки, підписки на події; перевизначення внутрішностей SimplyCMS не
  підтримується. Дані видаленого плагіна зберігаються, повне очищення — окрема
  явна дія.
- Статуси замовлень — довідник (дані), а не перерахування.

Прогалини Simetra, без яких вітрина й частина плагінів не переходять (ще не
мають віхи в Simetra): публічний режим хоста (публічні маршрути, читання
гостем, CDN-кеш, публічні URL файлів); `publicRead` з умовою («лише
опубліковане»); способи входу (email без пароля, OAuth); композиція модулів з
пакетів і розширення об'єктів вендора (П4-E Simetra).

### 🎯 Стратегічний напрям (затверджено власником 2026-08-19)

🔴 **У проєкту немає клієнтів і реальних магазинів — зворотна сумісність
не підтримується, різати по живому безпечно і правильно** (розширення D5
на весь стек). Затверджена звʼязка з трьох треків, у цьому порядку
залежностей:

1. **Бекенд-контракт v2** (ревізія D7): сервер-first дані (браузер не
   ходить у БД; PostgREST/GoTrue/supabase-js зникають), Better Auth,
   storage-порт, чистий Postgres як контракт (Supabase — один із
   підтримуваних провайдерів), «стек швидкості» вітрини (full-page кеш +
   CDN + фасети) і agent-readiness (JSON-LD скрізь, AI-robots) — усе одна
   реструктуризація. Іде ПЕРЕД відкриттям подач маркетплейсу (заморозка
   контрактів портів першим стороннім пакетом). Трек A (theme views)
   встиг завершитись ДО V2 — його контракту V2 не чіпає: переписуються
   контейнери/лоадери (шар даних), view-model-и і view-и лишаються.
2. **Маркетплейс**: модель поставки ухвалена (П1–П5: платформа і
   безкоштовні пакети — npmjs; платні — власний сервер доставки, лише
   scoped); реєстр `simplycms/marketplace` + вітрина на simplycms.dev.
3. **Хмара** (`simplycms/platform`, окремий приватний репо): Dokploy,
   1 магазин = контейнер застосунку + Postgres; кабінет
   Account→Organization→Store; код тенанта — «без git за замовчуванням +
   Підключити GitHub»; хмара ПЕРЕД платним тіром маркетплейсу.
