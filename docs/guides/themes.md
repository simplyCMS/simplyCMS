# Робота з темами — практичний посібник

> Аудиторія: **розробник магазину** (розділ 2) і **автор теми** (розділ 3).
> Це посібник «як зробити»; механізм, межі й те, як усе це верифікується, —
> [`../architecture/themes.md`](../architecture/themes.md) (джерело правди).
> Команди CLI детально — [`../architecture/cli.md`](../architecture/cli.md).
> Написано за підсумками Фази 4 (2026-08-14).

## 1. Три речі, які треба знати до всього іншого

1. **Тема — лише оформлення.** Design-токени, Header/Footer (обовʼязкові),
   опційні HeroBanner/HomeSections, власний каталог перекладів. Сторінки
   рендерить ядро (`@simplycms/storefront-routes`) — нова сторінка ядра не
   ламає жодну тему, але й замінити сторінку тема не може (свідома межа).
2. **Набір тем — build-time, активна тема — runtime.** Які теми ВСТАНОВЛЕНІ —
   каже `simplycms.config.ts` (мапа `themes:`), і зміна набору вимагає
   rebuild. Яка тема АКТИВНА — каже БД (`themes.is_active`, рівно одна), і
   перемикання з адмінки rebuild-у не потребує.
3. **Ідентичність теми — ключ у конфізі**, не імʼя npm-пакета і не
   `manifest.name`. Саме за ключем тему резолвить вітрина і саме він стає
   `name` рядка в БД. Ключ виводиться з імені пакета автоматично
   (`@vendor/simplycms-theme-aurora` → `aurora`) або задається `--name`.

## 2. Розробнику магазину

### 2.1 Встановити тему з npm

```bash
pnpm simplycms add @vendor/simplycms-theme-aurora --theme
pnpm build            # набір тем — build-time
# далі: /admin/themes → «Активувати»
```

Що відбувається під капотом: `pnpm add` → якірний запис
`'aurora': () => import('@vendor/simplycms-theme-aurora')` у
`simplycms.config.ts` → після rebuild тема зареєстрована в `ThemeRegistry`.
Рядок у таблиці `themes` заводить `bootstrapThemes` **при першому заході
залогіненого адміна** — тобто тема зʼявиться в `/admin/themes` не одразу
після деплою, а після першого візиту адміна. Це нормально.

🔴 **Tailwind-глоби для сторонніх тем.** Магазини, створені після Фази 4,
уже сканують `node_modules/simplycms-theme-*/dist` і
`node_modules/@*/simplycms-theme-*/dist`. Якщо магазин старіший — додай у
`content` свого `tailwind.config.ts` два рядки:

```
'./node_modules/simplycms-theme-*/dist/**/*.js',
'./node_modules/@*/simplycms-theme-*/dist/**/*.js',
```

Без них класи сторонньої теми мовчки випадуть зі скану (сторінка «гола»,
помилок нуль). `simplycms doctor` це ловить: перевірка «Теми» дасть warn з
готовим текстом глобів. Референс-теми ядра (`@simplycms/theme-*`) покриті
чинним глобом `@simplycms/*` — для них нічого додавати не треба.

### 2.2 Copy-in — повне володіння кодом

```bash
pnpm simplycms add @vendor/simplycms-theme-aurora --theme --copy
```

Shadcn-модель: сирці теми копіюються в `themes/aurora/` магазину, пакет
знімається. Далі це ТВІЙ код — прав як хочеш, але апстрім-фіксів більше не
буде. Обирай copy-in, коли тему плануєш суттєво перекроювати; лишай
npm-форму, коли хочеш отримувати оновлення автора через `pnpm update`.

Корисне про механіку (повний порядок — `themes.md` §3.2):

- залежності теми, яких немає в манифесті магазину, CLI **дописує в
  `package.json` магазину** перед зняттям пакета — інакше тема з власною
  бібліотекою не зібралася б;
- `--copy` несумісний із `--plugin` і `--no-install` (гучна помилка);
- повторний запуск, якому нема чого робити, — успіх (ідемпотентність);
- 🔴 та сама тема НЕ може жити одночасно npm-пакетом і копією під одним
  ключем: CLI впаде з підказкою `--name <key>` ДО будь-яких змін. Хочеш
  перейти з npm-форми на copy-in — спершу прибери старий запис із конфігу
  (і `pnpm remove` пакет), або дай копії інший ключ.

Copy-in-тема сканується наявним глобом `./themes/**` і резолвиться аліасом
`@themes/*` — жодних правок конфігів не треба.

### 2.3 Модифікація встановленої теми: два рівні

Прямої правки коду npm-теми не існує: пакет у `node_modules` — чужий код,
перший же `pnpm install` зітре зміни. Санкціонованих рівнів модифікації два:

1. **Без володіння кодом (npm-форма лишається).** Поверхня — рівно та, яку
   відкрив автор: `settings`-схема теми → форма в адмінці → значення в БД →
   `useThemeSettings()` у компонентах (§2.5). Натомість `pnpm update`
   продовжує приносити апстрім-фікси. 🔴 Часткового перекриття немає
   свідомо: «взяти тему з пакета, але замінити лише Header своїм» не можна —
   `components` приходить цілісним обʼєктом модуля, концепції child-теми /
   наслідування у v1 не існує. Гранулярність рівно дві: settings або повне
   володіння.
2. **Повне володіння — copy-in (§2.2).** Після `--copy` тема — звичайний
   локальний код проєкту: правиш `tokens.ts`, компоненти, `messages.ts` як
   власні файли; компілює їх Vite-збірка магазину, правки компонентів
   підхоплює dev-сервер, Tailwind сканує сирці (`./themes/**`) — нові
   utility-класи, яких не було в оригіналі, працюють одразу (у npm-формі
   сканується лише зібраний dist автора). Ціна — апстрім-фіксів більше не
   буде.

**Перехід npm → copy-in** (типовий цикл: пожив на пакеті → вирішив
перекроювати): прибери npm-запис із `simplycms.config.ts` + `pnpm remove
<pkg>` → `pnpm simplycms add <pkg> --theme --copy`. CLI навмисно НЕ дасть
формам співіснувати під одним ключем (помилка з підказкою `--name` ДО
будь-яких змін — §2.2). Рядок теми в БД привʼязаний до ключа, а не до форми
доставки — активація і збережені налаштування перехід переживають.

### 2.4 Активація, перемикання, «модуль відсутній»

Адмінка (`/admin/themes`) показує рядки таблиці `themes` і вміє рівно одне
перемикання: активувати обрану (усі інші деактивуються; інваріант «одна
активна» гарантує unique-індекс у БД). Кеш вітрини інвалідовується
автоматично після активації.

**Бейдж «модуль відсутній»** на картці теми означає: рядок у БД є, а модуля
в білді немає (пакет знято з конфігу, або рядок лишився від сід-міграції).
Кнопка «Активувати» для такої теми disabled — інакше адмінка показувала б
тему «активною», а вітрина тихо рендерила б `default` (SSR має триступеневий
fallback і не падає — але це розсинхрон, який плутає). Прибрати осиротілий
рядок можна SQL-ом — готовий запит є в `themes.md` §5.

🔴 Відомий випадок: **свіжий магазин одразу показує `solarstore` з бейджем
«модуль відсутній»** — рядок заводить сід-міграція, а шаблон реєструє лише
`default`. Це не поломка: постав тему пакетом
(`pnpm simplycms add @simplycms/theme-solarstore --theme`) або прибери рядок.

### 2.5 Налаштування теми

Якщо тема декларує `settings` (схему полів), адмінка рендерить форму на
`/admin/themes/<id>/settings`; значення зберігаються в `themes.settings`
(jsonb) і доїжджають у компоненти теми через `useThemeSettings()`. Тема без
`settings` показує «немає налаштувань» — це валідно.

### 2.6 Діагностика

`pnpm simplycms doctor` — перевірка «Теми» (warn-рівень) каже:

- чи КОЖЕН запис `themes:` конфігу резолвиться (тека `themes/<key>` для
  copy-in, пакет у node_modules для npm);
- чи не порожня мапа тем узагалі;
- чи не бракує Tailwind-глобів для встановлених сторонніх тем (§2.1).

Ще два знані нюанси, які НЕ є поломками (межі v1, деталі — `themes.md` §5):
`bootstrapThemes` — insert-only, тож версія рядка в БД може відставати від
версії пакета (адмінка покаже стару); оновлення метаданих рядків відкладено.

## 3. Автору теми

### 3.1 Старт — скаффолд у магазині

```bash
pnpm simplycms create theme aurora
pnpm dev              # правки видно після перезапуску dev-сервера
```

Команда створює `themes/aurora/` (manifest, tokens, messages, index,
components/Header, components/Footer, README) і дописує ключ у конфіг.
Build-кроку в локальної теми немає — це найшвидший dev-loop: редагуй
`tokens.ts`/компоненти й дивись результат. README скаффолда веде далі.

### 3.2 Контракт модуля (те, що перевіряється)

`src/index.ts` (у пакетній формі) чи `index.ts` (у локальній) робить
default-export обʼєкта:

```ts
const theme: ThemeModule = {
  manifest,     // { name, displayName, version, engines: { simplycms } }
  tokens,       // значення НАЯВНИХ semantic-змінних shadcn (+ dark-блок)
  components,   // Header, Footer — обовʼязкові; HeroBanner?, HomeSections?
  settings,     // опційно: схема налаштувань для форми в адмінці
  messages,     // опційно: власний каталог uk/en
};
export default theme;
```

- `validateThemeModule` (`@simplycms/themes`) — публічний валідатор; він же
  викликається при кожному `ThemeRegistry.load`, тож битий контракт видно
  одразу в dev. Окремої команди `theme:check` немає — перевіряє build/рантайм.
- `manifest.name` тримай рівним ключу конфігу — розбіжність дасть warn у
  консолі й плутанину в БД.
- `engines.simplycms` — semver-range сумісності з ядром; на 0.x
  невідповідність дає warn (строгий фейл — політика реліз-потяга v1.0).

### 3.3 Токени, а не CSS

Тема НЕ везе власний `theme.css`: `tokens.ts` задає значення наявних
semantic-змінних shadcn (`--primary`, `--background`, `--radius`, …), які
`applyTokens` розкладає в CSS. Темний режим — блок `dark` усередині tokens.
Кастомні utility-класи в компонентах — звичайний Tailwind; для npm-форми є
одна тверда вимога — див. §3.5.

### 3.4 i18n теми

Каталог теми (`messages.ts`, форма `{ uk: {...}, en: {...} }`) читається
хуком `useThemeT()` і живе ОКРЕМО від core-каталогу: класти рядки теми в
`packages/i18n` заборонено (зламало б типізацію ядра). `en` мусить
дзеркалити `uk` ключ-у-ключ. Core-рядки (назви сторінок, кошик…) бери
`useT()` — не дублюй їх у каталозі теми. Компоненти теми можуть вільно
використовувати хуки даних ядра (`@simplycms/core`) і `useSupabaseClient` —
межі довіри для тем немає свідомо (тема — довірена презентація, це контракт).

### 3.5 Публікація npm-пакетом

Конвенції (обовʼязкові — їх перевіряє й маркетплейс-контракт):

| Що | Вимога |
|---|---|
| Імʼя пакета | базове імʼя починається з `simplycms-theme-` (`simplycms-theme-aurora` або `@vendor/simplycms-theme-aurora`) |
| Entry | `src/index.ts`, default-export `ThemeModule`; `exports` лише `"."` |
| `files` | `dist` **і `src`** — без `src` у tarball-і не працюватиме copy-in (§2.2) |
| Збірка | tsup, ESM; 🔴 **класи мають лишатися літералами в dist-JS** — саме dist сканують Tailwind-глоби магазину; динамічна склейка імен класів = зникнення стилів |
| Залежності | `@simplycms/*` — **peerDependencies** (не dependencies: інакше в магазині зʼявиться другий інстанс React-контекстів на кшталт SupabaseProvider); `react`, `@tanstack/react-query`, `@tanstack/react-router`, іконки — теж peers |
| Сумісність | `engines.simplycms` у manifest |
| `description` | англійською (показується з npm-реєстру) |

Референс повного контуру — `packages/simplycms-theme-solarstore` у монорепо
платформи (для нього як пакета ядра конвенція deps інша — не копіюй її
сліпо; таблиця відмінностей — `themes.md` §3.1).

Локальний прогін перед публікацією: постав tarball у тестовий магазин обома
шляхами (`--theme` і `--theme --copy`), перевір активацію в адмінці й що
стилі на місці у production-збірці (`pnpm build && pnpm start`).

## 4. Шпаргалка

| Задача | Команда / дія |
|---|---|
| Створити свою тему | `pnpm simplycms create theme <name>` → правки в `themes/<name>/` |
| Поставити тему з npm | `pnpm simplycms add <pkg> --theme` → `pnpm build` |
| Поставити з повним володінням | `pnpm simplycms add <pkg> --theme --copy` → `pnpm build` |
| Перейти з npm-форми на copy-in | прибрати запис із конфігу + `pnpm remove <pkg>` → `add … --theme --copy` (§2.3) |
| Ключ зайнятий / інше імʼя | додай `--name <key>` |
| Активувати / перемкнути | `/admin/themes` → «Активувати» (rebuild не потрібен) |
| Налаштування активної теми | `/admin/themes/<id>/settings` |
| Перевірити стан тем | `pnpm simplycms doctor` (перевірка «Теми», warn) |
| Прибрати осиротілий рядок БД | SQL із `themes.md` §5 |

## 5. Чого тут немає (свідомі межі v1)

Повна заміна канонічних сторінок темою; runtime-встановлення (zip/URL);
uninstall-рядка з адмінки (достатньо деактивації); окрема команда
`theme:check`; оновлення метаданих рядка БД слідом за версією пакета.
Обґрунтування кожної межі — `themes.md` §1 і §8.
