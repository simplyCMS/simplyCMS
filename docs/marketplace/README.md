## 1. Що таке індекс

Індекс маркетплейсу — плаский JSON-файл (`{ "version": 1, "entries": [...] }`)
зі списком тем і плагінів, встановлюваних у магазин SimplyCMS через
`simplycms add <package> --theme|--plugin`. Кожен запис — публічні метадані
одного npm-пакета, зняті з його `package.json` і маніфесту
(`ThemeManifest`/`PluginManifest`), а не окрема декларація «на довіру».
`docs/marketplace/index.sample.json` у цьому репо — зразок формату з двома
живими записами (`@simplycms/theme-solarstore`, `@simplycms/plugin-faq`),
не робочий індекс.

## 2. Мінімальні вимоги подачі

Пакет **опубліковано на npmjs** (не приватний, не git-залежність) і задовольняє:

| Вимога | Деталі |
|---|---|
| Неймінг | Базове (unscoped) імʼя пакета починається з `simplycms-theme-`/`simplycms-plugin-` — сам пакет unscoped (`simplycms-theme-aurora`) або під будь-яким стороннім scope (`@vendor/simplycms-theme-aurora`). Виняток — референс-пакети ядра під `@simplycms/theme-<name>`/`@simplycms/plugin-<name>` (план Фази 4, Р1). |
| `license` | Валідний непорожній рядок у `package.json` (SPDX-ідентифікатор, напр. `MIT`). |
| `engines.simplycms` | Діапазон сумісності з ядром у маніфесті (`ThemeManifest`/`PluginManifest`, полі `engines`) — окреме поле від `engines` у `package.json` Node. |
| `description` | Англійською в `package.json` — це рядок, який бачить користувач у реєстрі/індексі, не UI-каталог i18n. |
| Для тем — валідний `ThemeModule` | Проходить `validateThemeModule` (`simplycms/themes`) без падіння: `manifest` + `tokens` + `components` за контрактом v2. |
| Для тем — конвенція залежностей | `simplycms` — **peerDependencies**, не `dependencies` (стороння тема не в реліз-потягу ядра; дублювання в `dependencies` подвоює React-контексти на кшталт `SupabaseProvider`). Деталі — план Фази 4, Р3. |
| `repository` | Публічне посилання на джерело (для аудиту й довіри перед додаванням). |

Ці вимоги перевіряє тільки **формат запису індексу** (Zod-схема в
`tests/marketplace-index.test.ts`); саму подачу — власник вручну до моменту,
коли з'явиться CI-конвеєр верифікації сторонніх пакетів (поза скоупом v1).

## 3. Процес подачі (після зняття гейту)

1. Опублікувати пакет на npmjs, що відповідає вимогам розділу 2.
2. Відкрити PR у репозиторій індексу (`simplycms/marketplace`, окремий репо
   — власника) з новим записом за схемою з `index.sample.json`.
3. Огляд власником: неймінг, ліцензія, `engines.simplycms`, для тем —
   ручна перевірка `validateThemeModule` і відсутність `simplycms` у
   `dependencies`.
4. Мердж PR публікує запис у живому індексі — окремому від цього монорепо.

До ухвалення позиції з розділу «Гейт власника» кроки 2–4 недоступні.
