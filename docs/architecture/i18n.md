# i18n: каталоги й повнота

Нові рядки інтерфейсу — через `simplycms/i18n` (`useT`/`createTranslator`), не хардкодом:
i18n-селектори `no-restricted-syntax` — **error**, тож новий кириличний рядок у зоні
валить лінт (`docs/development/TOOLING.md` § «Лінт»).

Рядки `head()` роутів вітрини (`<title>`, `<meta description>`) — теж через i18n (Е6б-10).
`head()` — звичайна функція поза React-контекстом, тож `useT()` там непридатний. Локаль і
профіль магазину приходять кореневим лоадером host-а (`StorefrontRootData.locale`,
`getStorefrontRoot` + `locale` у `src/routes/__root.tsx`) і читаються з `matches`.
Заголовок будують `storefrontHead(matches, (t) => …)` і `homeHead(profile)` із
`simplycms/storefront-routes/head/head` транслятором цієї локалі. Тека `storefront-routes/head`
клієнт-безпечна, тобто не server-only, як `storefront-routes/seo`: `head()` виконується і в
клієнтському бандлі.

🔴 Зелений лінт завершеності i18n **не доводить**: він бачить лише `JSXText` і три атрибути
(~64 % рядків). Доводять п'ять committed-тестів:

- `tests/i18n-coverage.test.ts` — AST-скан по `SCANNED_ROOTS` проти реєстру `PENDING_FILES`
  (реєстр **порожній**: останній борг — `head()` роутів ядра — закрито рішенням Е6б-10; новий
  кириличний рядок у зоні валить тест, а не додається в реєстр). Винятки-діагностика
  (`throw new Error`/`console.*` для розробника, не для покупця) — у `ALLOWLIST` того ж файлу;
- `tests/i18n-catalog-parity.test.ts` — повнота `en`;
- `packages/simplycms/src/i18n/__tests__/catalog-integrity.test.ts` — дублікати ключів;
- `tests/theme-messages-parity.test.ts` — повнота каталогів тем;
- `tests/plugin-messages-parity.test.ts` — повнота каталогів плагінів.

`SCANNED_ROOTS` (`tests/i18n-coverage/scan.ts`) — host `src/` і теки пакета ядра:
`storefront-routes`, `admin`, уся воронка (`cart-ui`, `catalog-ui`, `checkout-ui`, `profile-ui`,
`reviews-ui`), `core`, `storefront`, `themes`, `plugins`, `plugin-sdk`; плюс теми (тека `themes/`
і референс-пакети `simplycms-theme-*`) та плагіни (тека `plugins/` і референс-пакети
`simplycms-plugin-*`) — дискавляться з диска, не статичним списком. 🔴 Перелічені саме ТЕКИ, а не
`packages/simplycms/src` цілком: core-каталоги (`src/i18n/catalogs/**`) — кирилиця за побудовою.
Тобто `locale: 'en-US'` дає англійський магазин цілком.

🔴 **Каталогів ТРИ рівні, плутати не можна.** Core-каталог
(`packages/simplycms/src/i18n/catalogs/{uk,en}/`) типізований замкненим union-ом `MessageKey`.
Тема несе **власний** каталог (`ThemeModule.messages`, `themes/<name>/messages.ts`), читається
`useThemeT()`; плагін — власний `messages` у `definePlugin` (ключі з префіксом `plugin.<name>.`),
читається `usePluginT()` з `simplycms/plugin-sdk`. Класти копірайт теми/плагіна в core-каталог
заборонено: зламає типізацію ядра й змішає шари.
Метадані реєстру плагіна (manifest.description) — англійською: показуються з БД-рядка.

## Мови й мовні пакети

Тут — мови ІНТЕРФЕЙСУ. Тексти даних (товари, модифікації, значення властивостей, фото), адреси й
мовні токени — [`translations.md`](./translations.md); набір мов магазину (таблиця `languages`,
формат коду `LANGUAGE_CODE_FORMAT`, машина станів) у них спільний.

Дві осі мови не змішуються (спека §19.2): **мова контенту** (`ContentLocale`, `simplycms/contracts`) —
код із таблиці `languages` (`uk`, `pt-BR`, `pl`), а **мова інтерфейсу** (`UiLocale`,
`simplycms/i18n`) — код НАЯВНОГО мовного пакета (`uk`, `en`). Мови додає власник магазину в
адмінці, а ядро постачає пакети лише на етапі збірки, тож `UiLocale` створюють тільки `resolveUiLocale`
і `toUiLocale` (приведення `as UiLocale` деінде заборонене). Ядро постачає мовні пакети (`LanguagePack = { code, name, ui, content }`, реєстр `LANGUAGE_PACKS`):
сьогодні `uk` і `en` (обидва з повним каталогом інтерфейсу; таблиця транслітерації адрес за КМУ 2010 —
лише в `uk`). Вісь інтерфейсу — `ui`: ЛІНИВІ лоадери частин каталогу `base` (вітрина), `admin` і `mail`
(`import()`, кожна частина — окремий чанок, тож початковий граф вітрини не тягне текст адмінки й листів, І43).
Вісь контенту — `content` (`slugify`, місце під токенізацію пошуку `tokenize` зарезервоване й порожнє).
`getUiPack(ui)` — пакет мови інтерфейсу (кидає, якщо немає: `UiLocale` гарантує наявність);
`getContentTools(code)` — інструменти контенту за ТОЧНИМ кодом або `null`. Пакет НЕ обов'язковий: мова без
пакета — легальний випадок (`getContentTools` дає `null`, `hasUiPack(code)` — `false`), її інтерфейс іде
основною мовою магазину, а адреси з нелатинського тексту `slugify` не вгадує (`null` → власник вводить вручну).

**Міст осей — `resolveUiLocale(content, primary)`** (І41, І42): пакет із точним кодом → пакет базової мови
(`en-GB` → `en`) → ті самі кроки для основної мови магазину → інакше помилка з переліком наявних пакетів
(без тихого `uk`). Тому `/pl/…` без пакета `pl` показує дані мовою `pl`, а кнопки й заголовки — основною
мовою. `<html lang>` і запити даних лишаються за мовою контенту (`useContentLocale`); `I18nProvider`
і `head()` беруть мову інтерфейсу з даних кореня (`StorefrontRootData.ui = { locale, fallback }`).
`toUiLocale(value)` — лише ТОЧНИЙ код пакета (збережені значення), `hasUiPack(code)` — пошук пакета, як у мосту.

**Реєстр каталогів** (`simplycms/i18n`, `registry.ts`): `loadUiCatalog(ui, part)` повертає КЕШОВАНИЙ проміс із
протоколом thenable React (`trackThenable`, `simplycms/contracts/thenable`): завантажена частина розгортається
у `use()` синхронно, без suspend під час гідрації; відхилений проміс із кешу видаляється. Споживачі:
`useUiCatalogs(ui, parts)` (рендер: корінь вітрини — `['base']`, layout адмінки — `['base','admin']`),
`loadTranslator(ui, parts)` (сервер: листи, CLI) і `peekTranslator(ui, parts)` (`head()`: кидає, якщо частину
не завантажено — її чекає кореневий лоадер). `createTranslator(catalogs)` — синхронний, над завантаженими
частинами. Каталоги ядра ПОВНІ для кожної мови (англійські частини `satisfies Record<…Key, string>`), тож
fallback-мови в ядра немає; вона потрібна лише каталогам теми й плагіна, які можуть бути неповними.
Ключ частини `admin` поза адмінкою й ключ `mail` поза `simplycms/mail` забороняє сканер `i18n-coverage`.

🔴 Той самий ланцюжок «мова → основна мова магазину → ключ» — ОДИН `lookupMessage(catalogs, key, params)`
(`simplycms/i18n`) для транслятора ядра, каталогів тем (`useThemeT`) і плагінів (`usePluginT`): копій
`a ?? b ?? key` немає. Пару мов теми й плагіни беруть з `I18nProvider` (`useUiLocalePair()`); `useUiLocale()` —
мова інтерфейсу для форматування (дати, числа). `useLocale` (знесено)/`useFallbackLocale` (знесено): вони не казали, яка
це вісь.

**Мова запиту** (Мультимовність М1, І30/І36/І37) — `simplycms/domain` (`request-locale.ts`; хук `useContentLocale` — `simplycms/runtime/content-locale`):

- Єдине джерело — `resolveRequestLocale(pathname, set)` (`simplycms/domain`, T1: чиста функція без IO, тож її читають і лоадери, і хуки нижчих тірів): лише перший сегмент шляху, без cookie,
  `Accept-Language` і `Vary`. Лінт забороняє літерал `accept-language` у зоні вітрини
  (`tests/eslint-accept-language.test.ts`). Його кличуть нормалізація, `rewrite`, кореневий
  лоадер і екрани `NotFound`/помилки — другого парсера сегмента немає.
- `NotFound` і `errorComponent` кореня рендеряться поза `I18nProvider`, тож беруть транслятор з
  `useRequestTranslator()` (мова з `location.publicHref` через міст `resolveUiLocale`, набір мов з контексту матчу).
- Ключі кешу вітрини: `entityKey(entity, locale)` → `[entity, locale, …]`,
  `AGGREGATE.<x>.keyFor(locale)` → `[name, locale]`; ключі з видом цін — `[entity, view, locale, …]`
  (сегмент 1 належить виду цін, Р29). `createReadCache.get(load, { variant: locale })` — запис на
  мову під тим самим поколінням.

`languageOfConfigLocale(tag)` — тимчасовий міст до М2: `config.locale` магазину несе регіон
(`uk-UA`), а каталоги ключовані мовою (`uk`). Зникне разом із `config.locale`; для кодів мов
магазину (`pt-BR` — окрема мова) його застосовувати не можна.
