# Бекапи і тренувальне відновлення

## БД

Бекап налаштовано в Dokploy (щоденно, у S3-destination, ≥14 копій) ДО першого запису даних.
Ручний бекап перед ризиковою міграцією: Dokploy → Postgres → Backups → Run.

## Том / бакет

Бакет S3 копіюється засобами сховища (для Garage — реплікація чи `rclone sync` на окремий бакет; це крок власника).

## Тренувальне відновлення (обов'язкове, до приймання)

Прев'ю → згода. Відновлюй у ТИМЧАСОВИЙ Postgres 17 (окремий контейнер), а не поверх живої бази:

1. Завантаж останній бекап із destination (інструмент провайдера, ключі — з файлу секретів).
2. `pg_restore --no-owner -d <тимчасова база> <файл>` (або `psql` для plain-дампу).
3. `DATABASE_URL=<тимчасова база> pnpm simplycms doctor --online` — журнал міграцій на місці, власник є.
4. Порівняй кількість замовлень і товарів із живою базою (лише лічильники).
5. Прибери тимчасовий контейнер за його іменем. Результат (дата, розмір, час) — у підсумок.
