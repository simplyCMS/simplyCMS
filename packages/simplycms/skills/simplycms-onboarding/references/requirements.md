# Прийом вимог

Збери все ОДНИМ списком, покажи власнику й отримай згоду до першої мутації.

| Що | Приклад | Примітка |
| --- | --- | --- |
| Назва магазину (slug) | `my-shop` | латиниця, kebab-case; імена ресурсів Dokploy беруться з неї |
| Домен | `shop.example.com` | лише ім'я хоста, без схеми |
| Сервер Dokploy | URL панелі + `serverId` | `serverId` потрібен `prod-run` |
| Ключ API Dokploy | у файл секретів | власник вносить сам, не в чат |

`DOKPLOY_URL` — домен панелі з TLS (`https://`): ключ API йде заголовком, поза TLS (крім loopback) скрипти
друкують попередження «ключ іде відкритим текстом».
| DNS | Cloudflare, «DNS only» | запис А/CNAME створює власник або з явної згоди |
| SMTP | `SMTP_URL` + `MAIL_FROM` | `references/smtp.md`; без пошти запрошення власника не вийде |
| Сховище S3 | ендпоінт, регіон, бакет, ключі | `references/garage-bucket.md`; будь-яке S3 |
| Репозиторій | GitHub, гілка `main` | для autoDeploy |

## Власний Postgres на магазин (вимога платформи)

КОЖЕН магазин має ВЛАСНИЙ екземпляр Postgres, а не лише власну базу у спільному кластері.
Причина: ролі `app_runtime` і `app_admin` кластерні. Два магазини в одному кластері ділять їх:
синк пароля `app_runtime` одним магазином (накат на старті) ламає вхід іншому, а
`SET LOCAL ROLE app_admin` бачить чужу базу. Скіл не створює БД магазину в чужому кластері;
якщо власник пропонує спільний Postgres — відмов і поясни причину.

Перевірка після деплою: `pnpm simplycms doctor --online --production` (рядок `shared-cluster`).
