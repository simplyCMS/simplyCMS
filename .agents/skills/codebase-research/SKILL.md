# Codebase Research — simplyCMS

Мета: знайти **правильні місця** в коді за мінімум кроків і повернути **перевірені
факти**, а не переказ.

Модель, з якої все випливає:

> **Граф і `orient` дають КАРТУ** — де символ лежить і хто його споживає.
> **Файли дають ІСТИНУ** — сигнатури, типи, поведінка, що саме мокається в тестах.
> Карта без істини — здогад; істина без карти — читання навмання.

---

## 1. Вибір інструмента

Головний інструмент — скрипт `orient` із цього ж скіла. Далі в тексті це `orient`,
повний шлях від кореня репо:

```bash
.agents/skills/codebase-research/scripts/orient <аргументи>
```

Кличеться з будь-якої теки (корінь репо він визначає сам), у будь-якому агенті й
незалежно від наявності графа.

| Питання | Інструмент |
| ------- | ---------- |
| Де лежить символ? Кого зачепить його зміна? | `orient <Символ> [<Символ>…]` |
| Чи збігаються якорі плану (шляхи, `:рядки`, символи) з кодом? | `orient --plan <файл.md>` |
| Чи є граф і чи він свіжий? Чи немає привидів? | `orient --doctor` |
| Як влаштована незнайома область? | `graphify query "Symbol1 Symbol2 Symbol3" --budget 1500` |
| Як A досягає B? | `graphify path "A" "B"` |
| **Що саме робить код**: сигнатури, поля типів, поведінка, моки в тестах | **`Read` файлу** — граф цього не знає |
| Немає `graphify` (cloud `claude.ai/code`, свіжий клон) | той самий `orient` — усередині `rg`-fallback |
| Немає **терміналу** (Copilot у VS Code) | `search/usages` — references через language server, найближчий аналог `affected` |

`orient` не потребує знання синтаксису graphify і сам обирає бекенд. Прапорці:
`--depth N` (глибина зворотного обходу, типово 2), `--max N` (скільки споживачів
друкувати). Повний CLI графа — `references/graph-cli.md`.

## 2. Протокол дослідження

1. **Карта.** `orient` по ключових символах або `--plan` по файлу задачі.
   Не грепай наосліп до цього кроку: `orient` бачить транзитивних споживачів
   через барелі (`re_exports`/`imports_from`), яких `grep` не покаже взагалі.
   Приклад, перевірений запуском: `orient ThemeRegistry` дає 52 споживачі на
   глибині 2, зокрема ребро `theme-system/src/index.ts [re_exports]` — тобто
   всіх, хто бере символ через барель `@simplycms/themes`, а не прямим
   імпортом файлу. `git grep ThemeRegistry` показує лише прямі згадки й цей
   транзитивний шар пропускає.
2. **Істина.** Читай **лише** те, що показала карта, плюс місця, де питання
   поведінкове (типи, ролі DOM-елементів, поведінка бібліотек, фікстури й моки
   тестів). Граф про поведінку не знає нічого.
3. **Перевірка.** Якщо граф суперечить диску — не «домальовуй», іди в §3.
4. **Звіт.** Формат — §4.

Ознака, що ти робиш зайве: читаєш файл, щоб **знайти**, де щось лежить. Знаходить
`orient`; читання — щоб дізнатись **зміст**.

## 3. Протокол стейлу — коли граф збрехав

AST-хук на кожному коміті додає нове, але **не прибирає зникле**. Після rename чи
видалення в графі лишаються «привиди»: `explain` бадьоро віддає шлях, якого вже
немає.

| Симптом у виводі `orient` | Що це означає | Дія |
| ------------------------- | ------------- | --- |
| `ФАЙЛУ НЕМАЄ` | привид: файл перейменовано/видалено після останнього ребілду | `graphify update . --force` (~1 хв), потім повтори `orient` |
| `лише згадка в доках (…md), у коді немає` | символ живе тільки в планах/спеках — у коді його вже прибрано | перевір, чи запит не про стару назву (наприклад, `@simplysoftua/*` — scope перейменовано на `@simplycms/*` у Фазі 0) |
| `? у графі немає` | символ новий, зовнішній або локальний (не експортується) | звір `rg`, це нормально для щойно створеного коду |
| `orient --doctor` каже, що граф відстає від HEAD | ребілд не відпрацював (напр. коміт із `GRAPHIFY_SKIP_HOOK=1`) | `graphify update .` |

Після `--force` graphify може попередити, що назви спільнот застаріли — це
косметика звіту; за потреби `/граф-онови` (він же оновлює семантику `docs/`).

Граф у цьому репо щойно створений: частина символів може бути позначена як
«нова» навіть коли код давно існує — це наслідок першого проходу індексації,
а не привід одразу тягнутись за `--force`; спершу звір `rg`.

**Якщо після ребілду розбіжність лишилась — це дрейф ПЛАНУ, а не графа.**
Не «довіряй коду» мовчки: зафіксуй розбіжність у звіті явним рядком, бо рішення,
що робити зі скоупом, ухвалює власник задачі, а не дослідник.

Графа немає взагалі — не проблема й не привід зупинятись: `orient` уже працює
через `rg` і чесно позначає, що транзитивних споживачів не видно.

## 4. Формат звіту — дельта, не мапа

Повертай:

- **Відповіді на поставлені питання** — по одному абзацу, з `файл:рядок`.
- **Розбіжності з тим, що очікував замовник** (план, спека, припущення в запиті) —
  окремим списком, кожна з доказом: що написано → що фактично → де це видно.
- **Якорі** для подальшого читання: `шлях:рядок` + одне речення, що там.
- **Відкриті питання**, які потребують рішення власника.

Не повертай:

- дампи файлів і довгі блоки коду — цитата максимум ~10 рядків, і лише коли саме
  вона є доказом;
- інвентаризацію «усе, що я бачив» — замовник просив відповідь, не каталог;
- переказ того, що й так є в плані.

Причина жорсткості: звіт дослідника вкладається в промпти інших агентів, і кожен
зайвий кілобайт множиться на їхню кількість. При цьому виконавець однаково
перечитає файли — тож дамп не економить нікому нічого.

## 5. Анти-патерни (усі спіймані на реальних сесіях)

- **NL-речення в `graphify query`.** Матчер — case-folded підрядок + IDF: без
  стемінгу, синонімів і крос-мовності. Запит
  `"function that resolves the active storefront theme from the database on SSR"`
  повернув ноди сміття з markdown-планів. Питай **токенами-іменами**:
  `"getActiveThemeSSR ThemeRegistry applyTokens"`.
- **Читання файлу заради локалізації.** Один `Read` — це 2–5k токенів; `orient` —
  ~200 і показує більше.
- **Довіра графу без звірки з диском.** Див. §3; `orient` звіряє сам, сирий
  `graphify explain` — ні.
- **Копіювання дампу розвідки в промпт кожного виконавця.** Множиться на кількість
  агентів і не рятує їх від читання файлів.
- **Пошук по номеру рядка з плану.** Номери зсуваються навіть під час самої
  роботи. Шукай за унікальним текстом, номер — лише орієнтир.

## 6. Коли делегувати це субагентові

Точкове питання («де лежить X», «кого зачепить зміна», «чи збігається план») —
роби **сам**: `orient` дешевший і швидший за окремий раунд субагента.

Широке багатофайлове дослідження невідомого обсягу («розберись, як влаштована
підсистема X, і що треба знати, щоб зробити Y») — делегуй. Сенс делегування —
**ізоляція контексту**: субагент прочитає двадцять файлів у себе й поверне дельту,
а головна сесія лишиться тонкою. У Claude Code для цього є субагент
`codebase-research`, який працює саме за цим скілом.
